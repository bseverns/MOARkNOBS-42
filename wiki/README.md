## Publish to GitHub Wiki

1. Clone the wiki repo (replace with your remote):
   ```bash
   git clone git@github.com:<owner>/<repo>.wiki.git /tmp/mn42-wiki
   ```
2. Copy this folder's contents into that clone:
   ```bash
   rsync -av --delete wiki/ /tmp/mn42-wiki/
   ```
3. Commit and push:
   ```bash
   cd /tmp/mn42-wiki
   git add .
   git commit -m "docs: update project wiki"
   git push
   ```

## Maintenance model

- Keep deep technical detail in canonical docs (`README.md`, `docs/`, `firmware/README.md`, `bridge/README.md`, `App/README.md`).
- Keep the wiki as a navigation and onboarding layer for finished-instrument
  users, builders, and contributors.
- Keep generated visual aids reproducible. Signal-shape PNGs live under `wiki/assets/signal-shapes/` and are regenerated with `python3 tools/generate_signal_shape_pngs.py`. Workflow diagrams and annotated UI screenshots under `wiki/assets/ui/` are regenerated with `python3 tools/generate_workflow_graphics.py` from the checked-in UI source captures. Simulator-backed Stage screenshots are generated by `App/tests/mode_screenshots.spec.js`; use its Playwright capture artifacts when refreshing `stage-dashboard-simulator.png` or `stage-motion-simulator.png`.
- Every top-level content page must include a `Canonical source: \`path\`` line
  near the top.
- CI enforces both local markdown link integrity and canonical-source declarations.
- The wiki contract also checks a small set of high-risk condensed claims, such
  as the current LittleFS persistence model, so a valid source declaration
  alone cannot preserve a known-stale foundational label.
