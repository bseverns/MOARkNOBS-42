# Bridge Transport Contract

This document describes the desktop-side transport surfaces exposed by `bridge/` after the bridge runtime upgrade. It is intentionally conservative: it documents what the repo now exposes, not a promise that every external tool should depend on every field forever.

## Surfaces

- `Raw debug transport`
  `/ws`
  Newline-delimited firmware lines. This is the compatibility/debug lane and the fallback App-over-bridge path.
- `Structured event transport`
  `/ws/events`
  Newline-delimited JSON event envelopes for session-aware consumers.
- `Structured device/session API`
  `/api/device/session`
  Cached session snapshot.
- `Structured staged-config API`
  `/api/device/stage`, `/api/device/apply`, `/api/device/rollback`
  Bridge-side staging, validation, apply, and rollback discipline.

The App now prefers `/api/device/session` plus `/ws/events` when it is opened from the bridge. Raw `/ws` remains available both for compatibility and for the current live-control RPC lane.

## Structured event envelope

Every `/ws/events` frame is one JSON object with this shape:

```json
{
  "version": 1,
  "event": "device.ready",
  "at": "2026-05-24T12:00:00.000Z",
  "payload": {}
}
```

Rules:

- `version`
  Integer. Current value is `1`.
- `event`
  Stable event name string.
- `at`
  ISO-8601 timestamp generated by the bridge host.
- `payload`
  Object. Event-specific body.

## Event names

### `device.ready`

Emitted when the bridge has a complete cached device session: `HELLO`, manifest, schema, and config.

Payload:

```json
{
  "manifest": {},
  "schemaSource": "device",
  "firmwareIdentity": {},
  "powerSafety": {}
}
```

### `device.telemetry`

Emitted when the bridge sees telemetry-like device frames.

Payload:

```json
{
  "telemetry": {},
  "traceId": "serial-abc",
  "hostTimestampMs": 123456,
  "sourceTimestampMs": 123455
}
```

### `device.config.live`

Payload:

```json
{
  "config": {},
  "lastApplyResult": {}
}
```

### `device.config.staged`

Payload:

```json
{
  "config": {}
}
```

### `device.config.dirty`

Payload:

```json
{
  "dirty": true
}
```

### `device.apply.ack`

Payload:

```json
{
  "checksum": "sha256...",
  "seq": 7,
  "appliedAt": "2026-05-24T12:00:01.000Z"
}
```

### `device.apply.rollback`

Payload:

```json
{
  "reason": "checksum_mismatch",
  "lastApplyResult": {}
}
```

### `bridge.alert`

Machine-readable warning/error surfaced by the bridge runtime itself.

Payload:

```json
{
  "code": "malformed_device_response",
  "severity": "warn",
  "message": "Device returned malformed JSON",
  "details": {}
}
```

### `bridge.performance`

Payload:

```json
{
  "performance": {}
}
```

## Session API

### `GET /api/device/session`

Response:

```json
{
  "session": {
    "connected": true,
    "helloSeen": true,
    "ready": true,
    "schemaSource": "device",
    "manifest": {},
    "schema": {},
    "liveConfig": {},
    "stagedConfig": {},
    "dirty": false,
    "lastApplyResult": {},
    "powerSafety": {},
    "firmwareIdentity": {},
    "lastError": null
  }
}
```

### `POST /api/device/stage`

Request body:

```json
{
  "config": {}
}
```

Success response:

```json
{
  "result": {
    "staged": {},
    "dirty": true
  },
  "state": {}
}
```

Validation failure response:

```json
{
  "error": {
    "code": "schema_validation_failed",
    "message": "Staged config failed schema validation",
    "details": {
      "errors": []
    }
  },
  "state": {}
}
```

### `POST /api/device/apply`

Request body:

```json
{}
```

Success response:

```json
{
  "result": {
    "applied": true,
    "checksum": "sha256...",
    "seq": 7
  },
  "state": {}
}
```

Possible error codes:

- `device_not_connected`
- `device_not_ready`
- `schema_validation_failed`
- `apply_timeout`
- `apply_checksum_mismatch`
- `apply_transport_error`
- `device_<firmware error code>`

### `POST /api/device/rollback`

Request body:

```json
{
  "reason": "operator_request"
}
```

Success response:

```json
{
  "result": {
    "rolledBack": true,
    "reason": "operator_request",
    "state": {}
  },
  "state": {}
}
```

## Compatibility note

The raw `/ws` line transport remains intentionally unchanged for back-compat and deep debugging. The App-over-bridge path now prefers the structured session surfaces (`/api/device/*` plus `/ws/events`) and keeps raw `/ws` as a compatibility fallback plus the current live-control lane.
