# App Transport Truth Table

This page is the operator-facing tie-break for what the App means by each transport mode. It documents the current runtime behavior in `App/runtime.js`; it is not a promise that every mode is equally release-ready.

For bridge-side session and event contracts, see [Bridge Transport Contract](../bridge/BridgeTransportContract.md). For staged config versus live performance lanes, see [Bridge Write Lanes](../bridge/BridgeWriteLanes.md).

## Notes

- Bridge-served `/app/` should prefer bridge session whenever `/api/device/session` is available and healthy.
- Raw `/ws` remains an intentional compatibility fallback. It should not be removed or silently relabeled as bridge session.
- The transport chip and the connection banner are operator trust surfaces. If the active runtime state is `bridge-raw`, `bridge-session`, `direct-webserial`, or `simulator`, the labels must match that exact mode.
